# Standing directives

- **SD-001:** Start with the approved MVP boundary; do not pull later roadmap
  features into the current task.
- **SD-002:** Treat the producer's fast, low-training journey as the primary
  product outcome.
- **SD-003:** Keep regulated crop-protection products outside MVP0 ordering.
- **SD-004:** Keep the Mock ERP isolated behind a domain-owned adapter contract.
- **SD-005:** The Mock ERP must not delay local order confirmation.
- **SD-006:** Preserve module ownership; do not create shared persistence access.
- **SD-007:** Use explicit tenant scoping where the current MVP boundary requires it.
- **SD-008:** Do not log, test with, or document real personal, commercial, or
  credential data.
- **SD-009:** Use curated fixture products only in MVP0; defer Agrofit ingestion.
- **SD-010:** Keep full fiscal, inventory reservation, prescription, payment, and
  real ERP work out of MVP0.
- **SD-011:** Verify every claimed behavior with automated evidence before task
  completion.
- **SD-012:** Name production classes, methods, attributes, components, database
  tables, and database fields in PT-BR. Use `camelCase` for fields and quote
  PostgreSQL identifiers; do not convert them to `snake_case`.
